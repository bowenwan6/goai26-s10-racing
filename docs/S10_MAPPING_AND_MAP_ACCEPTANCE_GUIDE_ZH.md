# S10 建图、验图与可通行语义指南

更新日期：2026-09-13  
适用对象：48 号 S10、106 定位板上的厂商激光惯性 SLAM，以及后续真实导航接入  
文档性质：现场操作与工程验收指南；不是厂商精度认证，也不表示当前真机导航链路已经完成

## 先给结论

一张“能保存、能打开、看起来像场地”的图，不等于一张机器人能可靠使用的导航地图。完整流程至少要连续通过下面七道门：

1. 传感器、时间同步和外参状态可用；
2. 走场覆盖充分，并形成有意义的重访或回环；
3. 厂商地图完整保存，原始目录和证据可恢复；
4. 离线检查几何、覆盖、高度和时间连续性；
5. 在原场地加载地图后，机器人能获得稳定的全局定位；
6. 可走、禁行、限速、必经和可绕行信息被单独建模并验证；
7. 从静止、遥控复走、低速分段到完整路线逐级通过实车验收。

**一次建图会话可以成功，但“一条路线只走一遍”通常不能证明信息已覆盖。** 最好在同一会话中让关键区域至少从两个方向或两个视角被观察，并在起点、转角、楼梯/坡道、窄口和相似走廊处安排重访。没有真值测量时，回环数、点云重叠和栅格分辨率都不能单独证明精度。

## 1. 当前系统到底在建什么图

48 号当前使用 106 定位板上的厂商 SLAM。已核实的处理链是：

```text
雷达点云 + IMU
    → 时间同步、惯性预测、点云去畸变
    → 激光惯性里程计 LIO
    → 关键帧、回环检测、位姿图优化 PGO
    → 三维点云 + 优化轨迹 + 二维占据栅格
```

当前地图目录不只是一个图片文件。至少应保留厂商输出的完整目录，包括 `full_cloud.pcd`、关键帧/轨迹/约束文件、`occ_grid.yaml` 和 `occ_grid.pgm`。只复制 PGM 和 YAML 可能够一个普通二维地图服务器显示，但不一定够厂商定位器重新定位。

当前实测栅格分辨率为 **0.05 m/格**。这只说明地图采样尺度，不代表定位误差是 5 cm。当前 `/ODOM` 的 `child_frame_id` 为空且协方差全为 0，也不能据此宣称厘米级精度。

手机上的稀疏预览也不是最终地图：它只为了现场观察而抽样；厂商 SLAM 仍使用原始输入，最终应以停止并完成后处理后保存的地图为准。

更完整的当前设备与命令证据见 [48 号官方定位与 SLAM 使用](S10_48_SLAM_ZH.md)。

## 2. 2026 年推荐的地图分层方式

最新的实用做法不是把所有信息涂进同一张黑白图，而是把地图拆成彼此可验证、可单独更新的层：

| 层 | 回答的问题 | 本项目建议载体 |
| --- | --- | --- |
| 原始证据层 | 当时传感器到底看到了什么 | 原始 rosbag/MCAP、日志、配置、校验和 |
| 几何/定位层 | 世界结构在哪里，机器人在哪里 | 厂商完整地图目录、三维 PCD、二维占据栅格、定位器 |
| 可通行层 | 某处对当前机器人是否可通过 | 坡度、台阶、净高、净宽、落差、地面质量及机器人能力模型 |
| 语义限制层 | 哪些地方禁止、限速或需谨慎 | keepout、speed、slow/caution 等掩码或多边形 |
| 路线拓扑层 | 必须经过哪里，哪些路可替代 | 有序航点或路线图的节点、边和约束 |
| 实时障碍层 | 此刻的人、箱子、门是否挡路 | 实时雷达/深度数据形成的局部代价地图 |
| 版本与验收层 | 这张图是否就是已批准版本 | 地图 ID、SHA-256、设备/配置身份、验收报告、回滚目标 |

这套分层有三个直接好处：场地几何不变时，可以只改禁行区；临时障碍消失后，不必重建整张图；路线规则改变时，也不用篡改原始点云。

Nav2 的官方环境表示同样采用静态层、实时障碍层、膨胀层和空间语义过滤器的组合；禁行、限速和优选通道都是独立于基础占据图的空间注释。当前 S10 还没有完成 Nav2 真机接入，所以这里是**设计目标**，不是现在点一下就会生效的功能。

## 3. 建图前：先定义“成功”

### 3.1 先画任务草图

在走场前，用纸或图片标出：

- 地图边界、起点和终点；
- 所有必须经过的门、检查点或关卡；
- 楼梯、坡道、平台边缘、落差、窄口和低矮障碍；
- 玻璃、镜面、强反光、长直且重复的走廊；
- 可能移动的人、门、车辆、桌椅和箱子；
- 可以形成小环路或回到已知地标的位置；
- 机器人可能需要绕行后重新汇入主路线的位置。

不要把“覆盖整张图片的百分比”当成目标。真正需要覆盖的是**任务相关走廊及其定位特征**，而不是地图外接矩形里的所有未知区域。

### 3.2 确定最小可见特征和安全余量

提前量出或估计：

- 机器人实际运动包络，不只量机身中心宽度；
- 最窄通道、最小转弯空间和边缘安全距离；
- 最小台阶、最大允许台阶、最大坡度和最低净高；
- 任务允许的航点误差、横向跟踪误差和停车距离。

工程上应满足：

```text
定位误差 + 控制跟踪误差 + 机器人外形不确定性 + 安全余量
    < 通道单侧剩余空间
```

如果这条不等式没有余量，不能靠“把地图分辨率调得更细”解决。

### 3.3 建立本次地图身份

地图名建议包含场地、楼层/路线、版本，不使用空格，例如：

```text
siteA_F1_full_v003
```

记录机器人编号、106 的系统时间、SLAM 软件/配置哈希、雷达和 IMU 话题、外参版本、操作人、场地状态和开始时间。同一张地图后续的语义区、航点和报告都必须引用同一地图 ID 或内容哈希，防止坐标贴到另一张图上。

## 4. 建图前检查

### 4.1 安全与场地

- 遥控器、急停和人工接管可用；现场始终有人监护；
- 清走无关人员和会移动的物体；不能清走的动态区域记入草图；
- 不在雨雾、镜面强反射或传感器被遮挡的条件下强行建图；
- 镜头或雷达罩干净，传感器固定没有松动；
- 起点选择在结构特征丰富、以后容易复现的位置，不选空旷中央或重复走廊中段；
- 室内用 `--indoor`，室外用 `--outdoor`，不能只看名字猜模式。

### 4.2 机器人与数据

在 106 上先做只读检查：

```bash
python3 ~/check_s10_slam.py --seconds 6 --require-ready
systemctl status mapping.service localization.service --no-pager
drmap --format json mapping status
drmap map list
```

至少确认：

- 雷达和 IMU 持续有新数据，没有时间倒退或异常延迟；
- 106 与传感器的授时检查通过；
- 没有另一个建图会话、录制或导航任务在运行；
- 磁盘空间足够，当前旧地图已经备份；
- ROS 消息 frame、测量时间和频率有记录；
- 机器人静止时位姿不会持续快速漂移。

当前设备的 PTP 启动检查通过只表示启动条件合格，不是定位精度认证。

## 5. 现场建图步骤

### 第 1 步：先预演命令，不改变状态

```bash
drmap --format json --dry-run mapping start siteA_F1_full_v003 --no-activate --no-rviz --indoor
drmap --format json --dry-run mapping stop
```

核对地图名和室内/室外模式。`--no-activate` 只表示不自动把新图设为定位地图；真正开始建图仍会暂停原定位流程。

### 第 2 步：开始建图并确认输入

```bash
drmap mapping start siteA_F1_full_v003 --no-activate --no-rviz --indoor
systemctl status mapping.service --no-pager
journalctl -u mapping.service -n 60 --no-pager
ros2 topic echo /SLAM_ODOM nav_msgs/msg/Odometry --once --qos-reliability best_effort
```

也可以使用已部署的手机入口 `http://10.21.41.1:8080/` 开始建图。手机页面关掉或熄屏不会停止 106 上的 systemd 建图服务，但重新打开后要先确认当前会话身份，不要因为页面没有响应而重复点击开始。

只有当雷达、IMU、`/SLAM_ODOM` 和日志都在持续更新后才开始走。网页提示“已开始”或服务显示 `active`，都不能单独代替收包检查。

### 第 3 步：先静止，再低速起步

启动后先静止数秒，让 IMU 和初始局部地图稳定。起步、转弯和上下坡都应平顺；避免急转、原地高频摇摆、跳跃、碰撞和长时间高速运动。运动过快会降低相邻扫描重叠并加重运动畸变。

### 第 4 步：按“主线 + 交叉观察 + 回环”走场

推荐路线：

1. 从特征丰富的起点沿主路线低速前进；
2. 到路口、门口和窄口时，保持安全距离，以不同朝向观察两侧结构；
3. 楼梯/坡道前后各留出一段平地，完整记录进入、通过和离开；
4. 对关键地标从第二个方向再观察一次；
5. 能安全返回时，回到已走区域形成大回环；
6. 开放单向路线无法回起点时，在若干局部区域走小环或折返，尤其是路线前、中、后段；
7. 最后重访一个明确地标，停稳后再保存。

建议让相邻扫描持续重叠。不要贴墙走；过于靠近墙面会让另一侧结构被遮挡，也不利于后续规划机器人完整轮廓。

### 第 5 步：关键地形做专项补扫

- **楼梯/坡道**：从正面、斜侧和上下平台观察；不要只在踏面中央走一遍；
- **平台边缘/落差**：保留足够安全距离，确保落差前沿和下方回波被看到；
- **窄口**：观察两侧边界、入口和出口，记录实际净宽；
- **玻璃/镜面**：改变角度复扫，并以实体边框、立柱等稳定结构辅助定位；
- **长直重复走廊**：在支路、门框、柱子等独特位置形成交叉观察，避免只沿中线直走；
- **多层重叠区域**：二维 XY 相同但高度不同的地方必须保留三维/楼层身份，不能只依赖一张扁平二维栅格。

### 第 6 步：停稳后正常停止并保存

```bash
drmap mapping stop
systemctl status mapping.service localization.service --no-pager
journalctl -u mapping.service -n 100 --no-pager
drmap map list
```

不要用杀进程、关 SSH、断电或单独 `systemctl stop mapping` 代替厂商的保存流程。应等待保存和地图后处理完成。

记录 `start` 返回的完整地图目录名。检查本次目录中的 `full_cloud.pcd`、`occ_grid.yaml`、`occ_grid.pgm` 及关键帧/约束文件都存在且非空。地图保存失败时先保留现场和日志，不要继续覆盖或删除原会话。

## 6. 保存后先备份，再分析

至少保留三份东西：

1. 106 上未经修改的厂商原始地图目录；
2. 电脑上的完整只读副本或归档包；
3. 文件清单、每个文件的大小和 SHA-256。

推荐的审查包结构如下；语义和报告放在厂商目录外，避免破坏原厂格式：

```text
map-bundle/<map-id>/
├── vendor-map/              # 原厂完整目录，只读
├── evidence/                # 日志、配置、文件哈希、设备身份
├── analysis/                # 可视化、覆盖和误差统计
├── semantics/               # 禁行、限速、楼层、可通行区
├── routes/                  # 航点、路线图、替代边
└── ACCEPTANCE.md            # 验收结论和回滚目标
```

任何去噪、裁剪、地图修补都只处理副本，并生成新的地图版本；不得悄悄覆盖原图。

## 7. 怎么确认“跑到的地方都覆盖了”

### 7.1 不能用这些指标单独证明覆盖

- 地图成功保存；
- 点数很多或文件很大；
- 回环数大于 0；
- 轨迹长度与估计路线长度接近；
- 整张占据栅格中未知格比例很低；
- 手机预览看起来“铺满了”。

未知格比例尤其容易误导：地图外接矩形会包含大量本来就无需探索的外围区域。应只在任务走廊、关键地形和定位需要的结构范围内计算覆盖。

### 7.2 推荐的覆盖验收表

为每个任务区域记录以下项目：

| 项目 | 通过条件 |
| --- | --- |
| 主路线 | 连续，无断裂、瞬移或跨层错误连接 |
| 路口/分岔 | 所有可能进入的边都被看见；禁行边也有明确边界 |
| 必经点 | 前后均有可定位结构，并从至少两个方向观察 |
| 楼梯/坡道 | 上下平台、过渡边、坡面/踏步和净宽完整 |
| 窄口 | 两侧边界清晰；以机器人完整包络检查，不只看中心线 |
| 重访 | 关键区域有相隔一段时间的再次观察，重叠后没有明显双墙 |
| 数据连续性 | 雷达、IMU、轨迹时间无异常倒退；长空档有现场解释 |
| 动态遮挡 | 人或移动物体离开后，关键结构已重新扫描 |

### 7.3 最可靠的确认方法

把事前草图做成“区域清单”，逐项在三维点云、二维栅格、轨迹和现场照片/测量中打勾。然后让机器人在原场地加载该图，分别在起点、中段、末段和每层的独特位置重新定位。只有离线覆盖和现场重定位都通过，才可把该区域标为已覆盖。

## 8. 怎么确认导入后机器人真的读得懂

“读得懂”应分四级验收：

### A. 文件级

- 完整目录文件数、大小和 SHA-256 与备份一致；
- PCD 可解析，点数与声明长度一致，XYZ 没有 NaN/Inf；
- `occ_grid.yaml` 引用的图片存在，分辨率、原点、阈值合理；
- 关键帧、轨迹和回环/约束文件编号一致；
- 地图身份明确，不靠目录日期猜测。

### B. 加载级

```bash
drmap map list
drmap map activate <完整地图目录名>
systemctl status localization.service --no-pager
journalctl -u localization.service -n 100 --no-pager
```

确认激活的是目标地图、定位服务没有重启循环、实时消息时间新鲜。激活会改变机器人的运行状态，应在原地图场地、机器人停稳、遥控器和回退方案就绪时执行。

### C. 定位级

- 厂商状态明确为正常、全局定位，而不只是服务 `running`；
- 当前雷达扫描与保存点云在墙、柱、门框、楼梯边缘等位置重合；
- XY 俯视和 XZ/三维侧视都检查，防止跨楼层“俯视刚好重合”；
- 静止 30 秒，位置和航向没有不可接受的跳变；
- 从多个已知位置冷启动或重定位，结果落在正确楼层和正确走廊；
- 人工遥控前进、后退、转弯后，地图中的运动方向和实际一致。

匹配误差指标或内点率是算法内部指标，不等同于与真实世界比较的绝对误差。

### D. 导航级

先让规划器只生成路径，不运动，确认路径不穿墙、不跨层、不贴边。再以低速短距离验证局部避障、定位丢失停车、人工接管和回滚。最后才做完整路线。

加载成功但 C 或 D 未通过时，这张图仍然不能用于自主导航。

## 9. 高度和位置到底有多准确

### 9.1 先分清四个量

- `occ_grid.yaml` 的 `resolution: 0.05`：二维格子大小；
- 点云的 Z：点相对地图坐标系的高度；
- 位姿的 Z：机器人消息参考点的高度，不一定是地面或脚底；
- 定位误差：估计位置与真实位置的差，需要独立真值才能测。

这四者不能互相替代。把栅格分辨率写成“定位精度 5 cm”是错误的。

### 9.2 当前地图给出的警告

现有开放路线地图中，优化轨迹与原始 LIO 轨迹的终点相对起点高度差相差很大；这说明位姿图优化明显改变了三维轨迹。因为现场确实跨楼层且终点没有回到起点，不能直接判定哪条错，也不能把优化后的高度当真值。详见 [现有地图离线验图报告](../../map-reviews/1209_01_F-20260912-175844/REVIEW.md)。

### 9.3 正确的精度实测

在最终地图坐标系里选择独立测量点：起点、终点、每层平台、坡道两端、楼梯顶/底、窄口中心和若干地标。用卷尺、激光测距、全站仪、RTK 或可靠场地图纸取得真值；至少覆盖路线前、中、后和不同高度。

每个点应：

1. 从不同方向接近并停稳多次；
2. 记录定位 XYZ、航向、时间和定位状态；
3. 计算重复性，以及对真值的 XY、Z、航向误差；
4. 分别报告中位数、95 分位和最大值，不只报最好一次；
5. 对楼梯高度、层高、坡道高差和平台平面拟合残差单独统计。

验收阈值不能照抄别的机器人，应由最窄通道、机器人包络、控制误差和任务容差反推。没有独立测量前，文档只能写“尚未测得绝对精度”。

## 10. 怎么表达能走、不能走、必须走和可以绕行

不要把四种语义混成一种黑白障碍：

| 人的意思 | 推荐表达 | 规划器行为 |
| --- | --- | --- |
| 永远不能走 | keepout 禁行多边形/掩码，加机器人轮廓膨胀 | 全局和局部规划都不得进入 |
| 正常可以走 | 几何空闲且通过可通行性验证的区域 | 可参与规划；未知区默认不自动当作可走 |
| 可以走但慢 | speed/slow zone | 进入前或进入时降低速度 |
| 尽量走这里 | 优选通道或较低路线代价 | 有条件时选择，不构成硬约束 |
| 必须经过 | 有序航点、路线图必经节点或检查门 | 当前点未确认通过就不推进到下一点 |
| 可绕道后继续 | 路线图中的替代边 + 局部避障 + 重汇入点 | 前方阻塞时绕行，仍回到下一个必经节点 |
| 临时不能走 | 实时障碍层或动态禁行区 | 障碍消失后可恢复，不改基础图 |
| 楼梯/特殊动作 | 带地形类型、进入方向和能力要求的路线边 | 只由具备对应能力的策略通过 |

### 10.1 禁行区

在 Nav2 方案中使用 Keepout Filter；同时配置与机器人真实 footprint 相符的膨胀。官方文档特别提醒：过滤器本身不会自动获得普通障碍层的膨胀效果；如果只限制中心点，机器人边角仍可能越界。

高台边缘、危险落差和安全法规要求的区域，不能只依赖普通软件地图。需要与现场物理隔离、可靠急停或经验证的安全限制共同设计；普通导航 keepout 不等于功能安全认证。

### 10.2 必经点和可绕行

自由空间规划器通常只关心如何到终点，并不知道“必须穿过 3 号门”。因此应把任务写成路线图：

```text
起点 → 必经门 A → 必经门 B → 终点
                    ├─ 常规边
                    └─ 备用绕行边 → 重汇入点
```

Nav2 Route Server 支持预定义路线图及边级语义；当前项目的仿真跟随器则使用严格有序航点，内部通过半径为 0.18 m，未通过当前点不会跳到后点。但仿真 `course.yaml` 的坐标不能直接给真机使用，必须在最终实机地图和定位坐标系中重新标定。

### 10.3 多楼层和相同 XY

二维占据图无法区分“同一 XY 的楼上与楼下”。如果路线存在叠层，应使用：

- 每层独立二维地图 + 楼层切换节点；或
- 保留三维地图和三维可通行判断；或
- 带 `floor/level` 标签的路线图，并对跨层边指定坡道/楼梯动作。

绝不能因为俯视图重合就让规划器从楼下直接连到楼上。

## 11. 怎么去噪音，又不删掉真正的障碍

### 11.1 先修原因，再滤结果

常见噪声及优先处理：

| 现象 | 常见原因 | 优先处理 |
| --- | --- | --- |
| 墙面出现双层或拖影 | 时间不同步、外参错误、运动过快、定位漂移 | 修时间/外参，降速并重建；不要只做离群点滤波 |
| 空中零散点 | 多径、雨雾、反射、量测离群 | 距离/强度检查、统计或半径离群滤波 |
| 人形残影、移动物体轨迹 | 动态目标被多帧累积 | 清场、重访、时序一致性或动态点移除 |
| 地面破碎 | 姿态/重力方向、地面模型或量程问题 | 校验 IMU、外参和地面拟合 |
| 栅格少量椒盐障碍 | 单帧噪声进入代价图 | 局部 Denoise Layer 或最小连通域过滤 |
| 整片地图错位 | 定位/回环错误 | 回到 SLAM 轨迹与约束排查，滤波不能修复 |

### 11.2 推荐的离线处理顺序

1. 保留原始 PCD 和 rosbag，不在源文件上改；
2. 去除 NaN/Inf、明显超出传感器有效量程的点；
3. 用 PassThrough 只裁剪明确无关的物理范围；楼梯场景不要随意裁掉 Z；
4. 用 VoxelGrid 降采样时，体素尺寸应明显小于需要保留的最小台阶、边缘或障碍；
5. 用 StatisticalOutlierRemoval 或 RadiusOutlierRemoval 删除稀疏离群点；
6. 对多帧数据做时序持久性/动态目标判断，保留稳定结构；
7. 重新生成副本地图，并对关键薄障碍、台阶沿和平台边缘做前后对照；
8. 统计删点比例、被删区域和导航结果，验收后才发布新版本。

PCL 官方提供 VoxelGrid、PassThrough 和 StatisticalOutlierRemoval 等基础方法。参数不能照抄示例：过强滤波会把细杆、台阶前沿和低矮障碍一起删掉。

### 11.3 运行时去噪与离线修图不是一回事

Nav2 的 Denoise Layer 用于去除实时代价地图中的小型椒盐噪声，不能修复错误定位造成的整片错位。官方还提醒高量程传感器用于全局代价图时可能带来很大的更新窗口和计算开销。优先在局部代价图、小范围、可回放数据上验证。

## 12. 人一直跟着机器人，会不会被拍进去

当前厂商建图已核实的 SLAM 输入是雷达点云和 IMU，不是相机图像。因此，**仅就当前地图 PCD 而言，不会像普通照片那样保存清晰人脸**；但人的身体会形成点云轮廓，可能被写入关键帧或全局点云，也会遮挡墙面并产生动态残影。如果另外录制了相机话题或现场视频，则当然可能包含可识别影像。

现场人员必须为了安全监护和遥控而跟随，但建议：

- 与机器人保持稳定安全距离，尽量走在已经扫描过的一侧；
- 不要反复横穿雷达前方，不要围着机器人转；
- 不要在门框、楼梯边、柱子等关键定位特征旁长时间停留；
- 人离开关键区域后，让机器人换一个视角再扫一遍；
- 不要为了躲开雷达进入机器人盲区或危险距离；安全优先；
- 发布或共享 PCD、bag、视频前，按数据范围检查并执行隐私处理。

人短暂出现通常不会让整个建图必然失败；持续贴近跟随、遮挡大部分视野或在回环处站成固定“地标”，才更容易影响地图和后续重定位。

## 13. 分阶段验收与放行条件

| Gate | 验收内容 | 不通过时 |
| --- | --- | --- |
| G0 输入 | 雷达、IMU、时间、外参、磁盘、接管 | 不开始建图 |
| G1 保存 | 厂商正常停止、后处理完成、文件齐全 | 保留日志和会话，不激活 |
| G2 几何 | 点云/轨迹连续、无明显双墙、跨层错误 | 定位原因排查或重建 |
| G3 覆盖 | 任务区域清单逐项通过、关键区有重访 | 补扫或重建 |
| G4 精度 | 独立检查点的 XY/Z/航向误差满足任务预算 | 不做自主导航 |
| G5 定位 | 原场地多点全局重定位、静止和遥控复走通过 | 回退旧图 |
| G6 语义 | 禁行、膨胀、限速、必经、绕行逐项验证 | 不发布路线 |
| G7 运动 | 静止→短距离→复杂关卡→全程逐级通过 | 回到上一安全阶段 |

每个 Gate 都应留下报告和地图哈希。后一个 Gate 不能反过来替前一个 Gate 补证据。

## 14. QA：常见和容易漏掉的问题

### Q1：跑一次真的能覆盖所有需要的信息吗？怎么确认？

不一定。一次**会话**可以包含多次观察并成功；一条路线只单向走一遍通常不足。按第 7 节的区域清单检查三维点云、二维栅格、轨迹、重访和原场地重定位。关键结构至少换方向观察，动态遮挡离开后补扫。

### Q2：有回环是不是地图就一定准？

不是。回环只说明系统接受了某些重访约束；错误回环会拉坏地图，局部回环也不能证明整条长路线无漂移。要同时查看回环分布、优化前后轨迹变化、扫描叠合和独立真值。

### Q3：没有回到起点，地图一定不能用吗？

不一定。开放路线可以建图，但全局漂移更难验证。应在路线不同位置制造局部小环或折返，并在起点、中段、终点设置真值检查点。不能把“终点未回原点”当作漂移测量。

### Q4：导入地图后怎么确认机器人读得懂？

依次做文件级、加载级、定位级和导航级验收。最关键的是：激活地图身份正确、定位为正常全局、实时扫描与地图在三维中叠合、多地点重定位正确、低速移动方向一致。只看服务运行或图片显示不算通过。

### Q5：地图分辨率 5 cm，是否表示位置精度 5 cm？

不是。分辨率是栅格采样尺寸。真正精度需要把定位结果与独立测量的检查点比较，并报告重复性、95 分位和最大误差。

### Q6：高度信息有多准确？

目前没有独立真值，不能给出可靠的绝对数字。用楼层高度、台阶高度、坡道两端高差和平台平面作为真值检查；同时确认位姿 Z 是机器人参考点高度，不是地面高度。

### Q7：怎么告诉机器人哪里不能走？

用独立 keepout 多边形/掩码，叠加正确 footprint 和膨胀，并在全局和局部规划中验证。危险边缘不能只依赖普通软件地图。

### Q8：怎么告诉机器人哪里能走？

“雷达没看到障碍”不等于能走。区域必须同时满足已观察、地面/坡度/台阶能力、净宽/净高、边缘安全距离和定位质量。未知区默认不要自动白名单化。

### Q9：怎么设置必须走、可以绕道走？

必经用有序航点或路线图必经节点；可绕行用替代边和重汇入点。局部避障只负责绕开临时障碍，不能默默跳过比赛必经点。

### Q10：怎么设置“尽量走这边，但必要时可离开”？

使用优选通道或路线代价，不要用硬禁行墙。必须准备另一条代价更高但仍通过可通行验收的边，并验证阻塞时确实能重规划。

### Q11：楼梯和坡道能不能只靠二维地图？

不能可靠完成。二维图可辅助平面定位和路线拓扑，但楼梯/坡道还需要三维高度、坡度、边缘、进入方向和机器人运动能力。上下层 XY 重叠时尤其需要楼层标签或三维表示。

### Q12：人跟着机器人会不会有问题？

当前雷达建图不会生成普通照片，但会记录人体几何并造成遮挡或残影。保持安全距离、减少横穿、避开关键地标，人离开后补扫。若 bag 含相机话题则另按影像隐私处理。

### Q13：可以在最终地图上直接手工擦掉噪点吗？

可以在副本上编辑，但必须保留原图、记录操作、重新编号和重新验收。先判断噪声是不是时间、外参或定位错误；否则“擦干净”只会隐藏根因。

### Q14：桌椅或门的位置后来变了，要不要整张重建？

固定结构大幅变化或定位特征改变时重建；临时物体应由实时障碍层处理；规则变化只改语义层。若静态图中的旧障碍长期消失，可发布经验证的新地图版本，不直接覆盖旧版。

### Q15：地图能不能从一台机器人直接拷到另一台？

只有传感器型号、安装外参、坐标约定、定位软件格式和机器人能力兼容并重新验收时才可能。文件能加载不代表另一台机器人有相同 footprint、爬坡能力或定位误差。

### Q16：为什么机器人在地图上显示了，但仍不能导航？

可能只有位姿显示，没有完整 `map → odom → base_link → sensors` 变换、实时障碍层、正确 footprint、控制器、失效停车或语义地图。显示是定位链的一部分，不是完整导航链。

### Q17：为什么俯视叠合看着对，机器人却定位到错误楼层？

不同楼层可能共享相似 XY 和结构。必须查看 Z/XZ/三维叠合、楼层标签、独特地标和高度连续性，不能只看二维图。

### Q18：什么时候应该放弃修图，直接重建？

出现大范围双墙、跨层错误连接、时间跳变、外参改变、错误回环导致整体扭曲、关键区长期被遮挡，或原始证据不完整时，应修复根因后重建。少量孤立噪点或小范围语义变化才适合后处理。

### Q19：地图越密越好吗？

不是。过密会增加存储和计算，仍可能包含重复点和动态噪声；过稀则丢失薄障碍和地形边缘。分辨率/体素应由最小关键特征和算力共同决定，并用导航任务验证。

### Q20：建图时能不能高速跑，节省时间？

不建议。高速、急转和强烈机身运动会降低扫描重叠并增加去畸变压力。先以稳定低速得到可靠地图；速度上限应在定位和控制分段验收后再提高。

### Q21：定位正常是否可以立刻跑完整路线？

不可以。还要检查路径不穿墙/跨层、禁行与膨胀、实时避障、丢定位停车、人工接管，再按短直线、转弯、坡道/楼梯、窄口和全程逐级放行。

### Q22：如何知道地图被悄悄换过或语义贴错图？

所有航点、禁行区、路线和验收报告都绑定地图目录名与内容 SHA-256。激活前后打印目标身份；哈希或坐标原点不匹配时拒绝加载语义层。

### Q23：应该保留多久的原始数据？

至少保留到地图退役，并覆盖事故/回归调查需要。磁盘有限时优先保留已发布地图对应的原始证据、配置、日志和关键场景 bag；删除策略必须有清单、备份和责任人，不能由现场工具自动清空。

### Q24：怎样判断定位开始变差？

同时监测全局/局部状态、匹配质量趋势、位姿跳变、静止漂移、传感器新鲜度和实时扫描叠合。单一阈值容易漏报；一旦掉全局、数据过期或位姿跳变，应停止自主运动并要求重新定位或人工接管。

## 15. 现场口袋清单

### 开始前

- [ ] 地图名、场地、楼层/路线和版本已记录；
- [ ] 遥控器、急停、监护和回退可用；
- [ ] 雷达、IMU、时间、磁盘和静止状态通过；
- [ ] 旧地图与配置已备份；
- [ ] 动态人员/物体已清理或标注；
- [ ] 主路线、关键地形、回环和补扫点已经规划。

### 走场中

- [ ] 启动后雷达、IMU、`/SLAM_ODOM` 持续更新；
- [ ] 平顺低速，关键区域从第二方向观察；
- [ ] 路线前、中、后均有重访/小环；
- [ ] 楼梯、坡道、平台边缘和窄口完成专项补扫；
- [ ] 人或移动物体离开后完成补扫；
- [ ] 异常时间、跳变或服务重启时停止继续采集。

### 保存后

- [ ] 使用 `drmap mapping stop` 正常保存；
- [ ] 后处理完成，目录和关键文件非空；
- [ ] 原始目录完整备份并生成 SHA-256；
- [ ] 完成几何、覆盖、高度和时间审查；
- [ ] 在原场地完成多点全局重定位；
- [ ] 语义层和路线绑定正确地图哈希；
- [ ] 分段低速验收通过后才允许完整自主路线。
