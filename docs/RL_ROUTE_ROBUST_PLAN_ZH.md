# S10 真机导航改造计划：地图给先验，现场自己纠偏

## 0. v3（2026-09-19，当前）：第一版就是名义控制器，鲁棒只在测到偏离时介入

**为什么推翻 v2。** v2 在第一版之上叠了一层层"一直开着"的保护（台阶上的落差/侧落差急停、卡住回退重试、局部栅格 A* 回线、跟线门控）。结果是在**没有任何扰动**的仿真里也停车：

| 位置 | v2 的表现 | 原因 |
|---|---|---|
| B 下段第一级台阶 | 3 个种子里 2 个在 WP05 后停住（"climb made no progress"） | 路线以约 55° 斜穿第一级立面，斜着的立面在 13×9 高度网格里留下一串未知格：侧落差判成"左边有落差"、前方判成"空洞"，1150 在"左转—右转"之间来回，永远不前进 |
| WP18→WP19 | 无扰动矩阵停车（"route blocked and no way round"） | 下台阶后跟随器报 BLOCKED，局部 A* 在粗糙地面找不到路，回退模式互相踢皮球 |
| 定位偏置 0.2 m | WP13 一开始就卡住 | 同上，局部栅格把地形读成障碍 |

第一版在这些地方都能直接过。所以 v3 **把第一版的控制器原样作为名义行为**（模式、参数都不变，保证"不比第一版差"），第一版真正缺的只有一件事：机器人不在路线应有的位置时怎么办——被推开、路上有地图没有的东西、打滑、原地不动。这部分作为**只在测到偏离时才介入**的恢复层加上去，一回到路线就交还给名义控制器。

### 0.2 恢复层：只在测到偏离时介入

| 触发（机器人自己测得到的量） | 动作 | 退出 |
|---|---|---|
| 走廊里有地图没有的东西：LiDAR 点比地图表面（0.3 m 内最高处）高出 0.2 m 以上（`map_check`，地图变化检测） | **DETOUR**：在地图栅格上做 A*（`map_planner`：0.1 m 栅格，未知/障碍/>0.3 m 落差为危险，离危险 < 0.4 m 不可走，坡 > 15° 或坎 > 0.1 m 不走，看到的新障碍点一并封掉），目标是障碍之后的路线点，纯追踪跟随 | 回到路线（横向 < 0.25 m）且过了目标段 → WALK |
| 离路线 > 0.8 m，或回线的直线穿过地图危险区 | DETOUR：同上，目标是前方 1–3 m 的路线点（永远不进下一个台阶区） | 同上 |
| 8 s 没有沿路线前进 | 先后退 0.3 m（身后在地图上是空的才退），再 DETOUR（地图 A* 重新规划） | 同上 |

DETOUR 驱动 J3100 时前进速度不低于 0.5 m/s（第一版对跟随器指令的规则）。WP24→WP25 的缓坡上，跟随器会避开约 10° 的上坡、往下坡偏出约 0.9 m，DETOUR 用地图路径拉回来；以 0.41 m/s 回线时 J3100 在坡上原地停住。提到 0.5 m/s 后，32 次里仍有 3 次在这里打滑、重试 3 次后停车，因为重试走的是同一条路。**未解决**，下一步：重试时把卡住的位置标进地图、把回线目标放远一些。
| 绕不过去（如窄通道里站着人） | **WAIT**：停车，每 1 s 重新检查/规划；障碍离开就继续 | 30 s 仍不通 → HOLD（等人） |
| 1150 在台阶上遇到新障碍 | 原地停（1150 不能绕），WAIT | 同上 |

偏离小于 0.8 m 且回线方向没有危险时，不启用任何新逻辑——第一版的追线本身就会把机器人拉回来。

试过但没有合入：无台阶横坡上把爬升修正从 12° 放宽到 25°。运动学单测里能压住侧滑，物理仿真里 1150 在 WP29→WP30 横坡上照样下滑约 1 m（它几乎不会右转），没有证据支持就不改。

### 0.3 调研依据

- 地图做先验、传感器只检测"变化"：地图变化检测（map-based change detection）是长期运行机器人的常规做法；这里逐点比较 LiDAR 与地图表面，给定位误差留 0.3 m 余量。
- 全局规划在先验地图上、局部只处理新障碍：Nav2 的全局代价地图 + 局部代价地图分层（Macenski 2020/2023）；地图 A* 使用代价感知栅格（Smac 规划器思路），把新观测到的障碍写入临时层。
- 名义控制器不因保护层变差：保护只在监测量越界时接管（run-time assurance / simplex 架构的思路），越界量都是机器人可测的：横向误差、前进进度、地图变化、速度。

### 0.4 验收结果（GPU 服务器 MuJoCo 全程，c02d598）

两个版本都在同一台服务器上跑，用同一张地图、同一对 policy（J3100 步行、1150 台阶），只换随机种子（传感器噪声、点云丢点）。腿式 policy 对微小数值差异很敏感：同一个种子在 Mac（ARM）和服务器（x86）上结果不同，所以只看多种子的完成率。v3 的仿真还按真机 SDK 的方式切换 policy：J3100 → 1150 边走边切，1150 → J3100 要经过 0.25 s 的 SafeHold。第一版的仿真是瞬间切换。

| 全程 WP01→WP30 | 第一版（24 个种子） | v3 c02d598（32 个种子） |
|---|---|---|
| 跑完 | **4/24** | **19/32**（上一版 49fd514：23/32） |
| 翻倒 | 11（WP15 横坡 10、WP11 岩脊 1） | 5（B 楼梯 3、WP27→WP29 高台 2） |
| 停车 / 卡住 | 9（WP14 坎 4、WP11 岩脊 2、WP24→25、WP28→29、WP29→30 各 1） | 8（WP24→25 缓坡 3、漏打 WP04 或 WP11 后无路可回 2、WP11→12、WP27→28、WP28→29 各 1） |
| 跑完的用时 | 723–750 s | 611–655 s |
| ≥1 s 的停顿 | 3–9 次 | 0–2 次 |
| 航向来回（0.5 s 平滑后 \|ω\|>0.1 rad/s 换号，每 100 m） | 116–126 | 62–78 |
| 平均速度 | 0.38 m/s | 0.43–0.45 m/s |

v3 的"停车"是按设计停下并报告原因（例如漏打的航点在 J3100 不能走的地形上），不乱走。第一版的"卡住"是 45 s 没有沿路线前进。

鲁棒性测试：全程加一种扰动，每种 4 个种子，共 **14/28** 跑完。

| 扰动 | 跑完 |
|---|---|
| 定位偏置 0.1 m / 2° | 1/4 |
| 定位偏置 0.2 m / 3° | 2/4 |
| 定位噪声 3 cm / 1°（每帧） | 2/4 |
| 运行中被横向推开 0.6 m（6 次） | 3/4 |
| 运行中被横向推开 1.0 m（6 次） | 3/4 |
| 路线上放地图没有的箱子（4 个） | 3/4 |
| 偏置 + 噪声 + 推开 + 箱子 | 0/4 |

失败原因分布：翻倒 7 次，其中 B 楼梯 4 次、M09 台阶平台 1 次、WP14 坎 1 次、高台 1 次。停车 7 次：漏打 WP04 后停车 3 次（都是 seed 3），WP24→25 缓坡 2 次，B 楼梯下段 1 次，WP11→12 1 次。被推开和放箱子时，地图 A* 回线和绕行都起了作用；定位误差主要伤在 B 楼梯。

**剩下的问题**，按风险排列：

1. **B 楼梯（WP05→WP08）**。第一版 24 次都过了（它的失败都在后面），v3 无扰动 32 次里失败 3 次，扰动测试里 5 次。失败时 1150 斜着顶在立面上停住（第三跑立面与前进方向差 17–24°），然后侧滑下 2–4 m 的边。v3 在这里比第一版差的原因还没查清，是下一步的重点。可能的原因：起步时的转向限制、SafeHold、ALIGN 侧移的差别。
2. **WP27–WP29 高台**：1150 在坡上后滑，翻倒或 25 s 上不去（停车）。
3. **WP24→WP25 缓坡**：只停车、不翻倒，见 §0.2。

视频：仿真地形每个区域只有一种颜色，台阶在画面里看不出来。视频叠加层现在把路线经过的每一级台阶画成品红横条（按地图检测到 43 处），走近时标出高度（s10-rl-sprint 5fa5f49、b80440d，只影响视频）。

## 附：v1/v2 计划（历史记录，已被 v3 取代的部分见 §0）

## 1. 原则

1. 路线可以优化，但每一处修改在真机上都要成立。地图（v3 点云）只提供**先验**：哪一段需要换 policy、台阶大概在哪、朝向大概多少。**是否进入、朝哪对准、何时退出，都由现场感知决定。**
2. 不依赖仿真真值，也不依赖定位绝对准确：目标是在定位偏差 0.3 m / 5° 时仍能完成。
3. 偏离路线时由算法纠正（代价感知 A*），不做"盲跟示教线"。
4. 沿用 `strategy.Router` 的不变量：任何时刻只有一个指令源；传感器过期、翻倒、力矩持续超限就停；恢复有次数上限。

## 2. 仿真版里哪些做法到真机不成立

| 仿真做法 | 真机上的问题 | 真机做法 |
|---|---|---|
| 台阶区用 MuJoCo 地形真值沿中心线算出 | 真机没有真值 | 离线从 v3 点云地形标注（先验），现场用高度网格确认台阶边 |
| 手工改线（overrides）照着 MuJoCo 画 | 线本身画在同一张地图上，真机同样成立；问题是盲跟：地图误差 + 定位误差会让机器人偏离线 | （v2）验证过的手工线作为冻结段保留；偏离由现场感知纠正（实测台阶边对准、居中、A* 回线）；其余段落算法生成 |
| 对准方向 = 路线切线 | 定位偏航 5° 就会斜着上台阶 | 对准实测台阶边的法线（RANSAC 拟合） |
| router 回线时绕过规划器，盲跟示教线 | 看不见障碍 | 代价感知 A* 回线（按当前 policy 能力设代价），A* 失败才停车 |
| 退出台阶区看弧长 s | 定位误差会提前/延后切回 | 高度网格确认：机身下和前方 0.3 m 没有台阶边，高度接近上层平台 + 俯仰 < 5° |
| WP06、WP07 在仿真里挪了 0.6 m | 只在仿真地图成立 | 现场标点确认；途中靠居中和绕行保证安全 |
| 清掉路线 1 m 内的树冠方块 | 仿真地图专用 | 真机上由 conservative scan 的高度带决定，需要现场确认树冠高度 |

## 3. 架构

```

                                   └► maneuvers.json（每个台阶区：s 区间、先验台阶边线/法线/高度、
                                                     需要的 policy、进入窗口、退出条件）
运行：定位 + /NAV_POINTS ──► 高度网格 13×9（多帧融合）
          ├─► EdgeTracker：立面格 → RANSAC 直线 → 距离 / 法线 / 台阶高 / 置信度，与先验做门限融合
          └─► 可通行栅格（按当前 policy 能力分级）──► RouteFollowerCore（Frenet 候选 + A* 兜底）
      strategy.Router：NAVIGATE → APPROACH → ALIGN → CLIMB_READY → CLIMB → VERIFY_CLEAR → HANDOFF
          └─► /cmd_vel + /strategy/joint_owner（official=J3100 / stairs_stable=1150）──► SDK runner
```

## 4. 算法选型（调研结论）

- **台阶边检测**：高度网格里找相邻格高差超过阈值的"立面格"，用 RANSAC 拟合直线得到边线；输出距离、法线、台阶高、内点数。这是阶梯建图和台阶跟踪里的常规做法（分段 + RANSAC 拟合、立面线拟合）。与地图先验做窗口门限（±0.5 m、±20°）：测量落在窗口内才采用，否则按先验慢速接近，仍找不到就停。
- **可通行性**：每格按坡度、粗糙度、台阶高三项加权（与 elevation_mapping 的 traversability 层同一思路）。阈值按**当前 policy**：
  - J3100：台阶 ≤ 6 cm（且速度 ≥ 0.5 m/s）、纵坡 ≤ 12°、横坡 ≤ 5°。
  - 1150：台阶 ≤ 18 cm、纵坡 ≤ 20°、横坡 ≤ 10°、只能直走。
- **纠偏 / 回线**：保留 Planning 规划器的 Frenet 横向候选；兜底的 A* 改成代价感知（可通行代价 + 偏离示教线代价），与 Nav2 Smac Hybrid-A*、ETH art_planner 的思路一致。锐利台阶的立面格不再判为"未知 = 障碍"，而是带高度的"台阶边"格，由当前 policy 的能力决定能否通过。
- **跟线**：Regulated Pure Pursuit（按曲率和离障碍的距离调速），加最低速度约束（J3100 在非平地 ≥ 0.5 m/s，否则会卡在小坎上）。
- **切换 policy**：路线标注只给出"允许开始切换的区间"。真正切换由 Router 的 ALIGN 门在感知条件同时满足并保持 0.4 s 时触发：
  - 距实测台阶边 0.45–0.70 m；
  - 对实测法线的航向误差 ≤ 6°；
  - 横摆角速度 ≤ 0.1 rad/s；
  - 速度 ≤ 0.3 m/s。

  这和"检测到台阶地形进入台阶模式、通过后切回"的做法一致。
- **1150 爬升时的控制**：航向保持在实测法线 ±12° 内（它几乎不会转向）；横向只通过小角度航向偏置修正，偏置由左右落差的居中量给出；按实测前进速度压指令，因为它会超速。
- **确认通过（VERIFY_CLEAR）**：高度网格显示机身下和前方 0.3 m 没有台阶边、后轮已过最后一道边 0.6 m、俯仰 < 5°，持续 0.4 s。任何一项拿不到就判失败（fail closed）。
- **错过 WP**：1150 越过未到达的 WP 就停下，切回 J3100 原地转向补点。

## 6. 验收指标

- 仿真：每段 10 个随机种子成功率 ≥ 90%；定位偏置 0.2 m / 3° 下成功率下降不超过 10 个百分点；零摔倒；急停线（45 / 12 N·m、25.8 / 30 rad/s）越线时间计入报告。
- 真机：按 native 计划，每段连续两次通过再串联；人工接管、急停、失败分别记录，不计为成功。

## 7. 顺序

1. B + C + D 核心算法和单测。
2. E 接入 Router（ROS 无关核心 + 节点参数）。
3. F 仿真鲁棒性测试。
4. A runner 与队友对接。
5. G 现场。
