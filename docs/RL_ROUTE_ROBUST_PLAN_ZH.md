# S10 真机导航改造计划：地图给先验，现场自己纠偏

## 0. v2 修订（2026-09-19）：第一版算法是名义行为，鲁棒层只在偏离时介入

**目标**：第一版（仿真 30/30、713 s、有视频的那版）在真机上照样能跑，平顺程度不低于它；偏离路线、遇到障碍、定位或地图不准时，能自己回到路线、做对决定。

**结论：继续现在的方案，但修两处。** 依据是同一段（WP01→WP10）的平顺度对比：

| 指标（WP01→WP10） | 第一版 full_v3（真值定位、手工线） | 真机栈 r13（算法路线、感知门控） |
|---|---|---|
| 用时 / 平均速度 | 145.2 s / 0.409 m/s | 147.8 s / 0.405 m/s |
| ≥1 s 的停顿 | 0 | 1 次，1.7 s |
| 航向来回（0.5 s 平滑后角速度换号） | 56 | 72 |
| 对准（ALIGN）时间 | 4.6 s | 9.3 s |

框架（WALK/APPROACH/ALIGN/CLIMB/REJOIN）和第一版一致，速度持平，多出来的是现场测量的台阶边门控、A* 回线、跌落/空洞保护、错过 WP 处理。差距有两处：

1. **路线**：第一版用的是在地图上逐段验证过的线（`route_sim/overrides_v1.json`，8 段手工线 + WP06/WP07 仿真挪点）。真机栈改用算法生成（DP 居中 + 走廊重规划 + 弹性带），B 台阶已经和手工线一样能过，但 WP11 附近生成了绕圈（第一版此处是手工直线），在这里停住。**改法**：手工验证过的段落作为"冻结段"原样保留（地图上画的线，在同一张地图定位的真机上同样成立），算法只处理其余段落并对全线做校验报告；策略改进后（队友泛化 policy），能力表一改，算法段自动跟着变，冻结段按报告逐段放开。
2. **验证方式**：鲁棒性要单独测，不能只看一次成功。加入推离路线、路上放障碍、定位偏置/噪声、地图先验误差，每次都和第一版比平顺度。

### 0.1 分层（第一版 = L0–L2 的名义行为）

| 层 | 名义行为（和第一版一样） | 偏离时介入 |
|---|---|---|
| L0 路线 | 第一版的线（冻结段）+ 其余段算法居中；全线平滑穿过 WP | 校验报告：离落差距离、台阶斜穿角度（≤ 1150 能力 25°）、横坡 |
| L1 跟线 | 纯追踪（RouteFollowerCore），J3100 速度 ≥ 0.5 m/s | 跟随器拒绝（BLOCKED/OFF_CORRIDOR）→ A* 回线；看不到路线就原地转头去看 |
| L2 切 policy | 台阶区前对准、1150 过区、确认后切回 J3100 | 对准用**实测**台阶边（RANSAC）而不是地图；地图先验偏 0.5 m / 20° 以上就不进；前轮已顶到台阶也可以切 |
| L3 安全 | — | 前方落差或空洞（连续两行未知）→ 1150 原地停并转向宽的一侧，4 s 不解除就 HOLD；倾角 45° → stop；传感器过期 → 停 |
| L4 恢复 | — | 错过 WP：用自身投影判断，台阶上不回头，出台阶后在平地补点；其它失败 HOLD 并给原因 |

### 0.2 调研要点（选型理由）

- 跟线与调速：Regulated Pure Pursuit（Nav2，Macenski 2023）——按曲率和离障碍距离降速，名义行为不停车。
- 路线平滑：弹性带（Quinlan & Khatib 1993，TEB 的基础）——在 WP 固定的前提下最小化曲率，同时保持离落差距离；加"台阶上航向不偏离立面法线 25° 以上"的约束（1150 实测会自己转正、几乎不能侧移：vy=0.15 m/s 时 6 s 只侧移 5 cm）。
- 回线/绕障：代价感知 A*（Nav2 Smac / ETH art_planner 思路）在跟随器的局部栅格上规划；目标点在视野外时先转头观察（主动感知），而不是乐观地把未知当可走。
- 切换时机：地形触发的技能切换（轮腿机器人按地形切运动模式；ANYmal 跑酷的"感知导航模块选技能"）——地图给允许区间，现场测量决定时刻。
- 台阶边：高度图立面格 + RANSAC 直线（阶梯建图常规做法），与地图先验做窗口门限。

### 0.3 验收（每次改动都跑）

- 平顺度对第一版：全程用时 ≤ 713 s × 1.1；≥1 s 停顿次数不多于第一版；航向来回次数不多于第一版 × 1.2；急停线零越线。
- 鲁棒性矩阵（每项 3 个种子）：定位偏置 0.1/0.2 m × 2/3°、噪声 0.03 m/1°；地图先验 ±0.2 m / ±8°；平地和台阶平台处横向推离 0.5–1.0 m；平地路线上放 0.4 m 障碍箱。报告成功率、WP 真实距离、回线用时。
- 现场顺序不变：零速 → 短距 → 单台阶区 → 分段 → 全程。

分支 `rl/maneuver-router`（基于 `nav/route-v2-integration` 684ffc1）。适用：J3100 步行（official 槽）+ 1150 台阶（stairs_stable 槽），route_v2 的 30 个官方 WP。

## 1. 原则

1. 路线可以优化，但每一处修改在真机上都要成立。地图（v3 点云）只提供**先验**：哪一段需要换 policy、台阶大概在哪、朝向大概多少。**是否进入、朝哪对准、何时退出，都由现场感知决定。**
2. 不依赖仿真真值，也不依赖定位绝对准确：目标是在定位偏差 0.3 m / 5° 时仍能完成。
3. 偏离路线时由算法纠正（代价感知 A*），不做"盲跟示教线"。
4. 沿用 `strategy.Router` 的不变量：任何时刻只有一个指令源；传感器过期、翻倒、力矩持续超限就停；恢复有次数上限。

## 2. 仿真版里哪些做法到真机不成立

| 仿真做法 | 真机上的问题 | 真机做法 |
|---|---|---|
| 台阶区用 MuJoCo 地形真值沿中心线算出 | 真机没有真值 | 离线从 v3 点云地形标注（先验），现场用高度网格确认台阶边 |
| 手工改线（overrides）照着 MuJoCo 画 | 线本身画在同一张地图上，真机同样成立；问题是盲跟：地图误差 + 定位误差会让机器人偏离线 | （v2）验证过的手工线作为冻结段保留；偏离由现场感知纠正（实测台阶边对准、居中、A* 回线）；其余段落算法生成 |
| 对准方向 = 路线切线 | 定位偏航 5° 就会斜着上台阶 | 对准实测台阶边的法线（RANSAC 拟合） |
| router 回线时绕过规划器，盲跟示教线 | 看不见障碍 | 代价感知 A* 回线（按当前 policy 能力设代价），A* 失败才停车 |
| 退出台阶区看弧长 s | 定位误差会提前/延后切回 | 高度网格确认：机身下和前方 0.3 m 没有台阶边，高度接近上层平台 + 俯仰 < 5° |
| WP06、WP07 在仿真里挪了 0.6 m | 只在仿真地图成立 | 现场标点确认；途中靠居中和绕行保证安全 |
| 清掉路线 1 m 内的树冠方块 | 仿真地图专用 | 真机上由 conservative scan 的高度带决定，需要现场确认树冠高度 |

## 3. 架构

```
离线：v3 点云地形 ──► maneuvers.py ──► route_v2.json（官方 WP 不变，可附优化后的中心线）
                                   └► maneuvers.json（每个台阶区：s 区间、先验台阶边线/法线/高度、
                                                     需要的 policy、进入窗口、退出条件）
运行：定位 + /NAV_POINTS ──► 高度网格 13×9（多帧融合）
          ├─► EdgeTracker：立面格 → RANSAC 直线 → 距离 / 法线 / 台阶高 / 置信度，与先验做门限融合
          └─► 可通行栅格（按当前 policy 能力分级）──► RouteFollowerCore（Frenet 候选 + A* 兜底）
      strategy.Router：NAVIGATE → APPROACH → ALIGN → CLIMB_READY → CLIMB → VERIFY_CLEAR → HANDOFF
          └─► /cmd_vel + /strategy/joint_owner（official=J3100 / stairs_stable=1150）──► SDK runner
```

## 4. 算法选型（调研结论）

- **台阶边检测**：高度网格里找相邻格高差超过阈值的"立面格"，用 RANSAC 拟合直线得到边线；输出距离、法线、台阶高、内点数。这是阶梯建图和台阶跟踪里的常规做法（分段 + RANSAC 拟合、立面线拟合）。与地图先验做窗口门限（±0.5 m、±20°）：测量落在窗口内才采用，否则按先验慢速接近，仍找不到就停。
- **可通行性**：每格按坡度、粗糙度、台阶高三项加权（与 elevation_mapping 的 traversability 层同一思路）。阈值按**当前 policy**：
  - J3100：台阶 ≤ 6 cm（且速度 ≥ 0.5 m/s）、纵坡 ≤ 12°、横坡 ≤ 5°。
  - 1150：台阶 ≤ 18 cm、纵坡 ≤ 20°、横坡 ≤ 10°、只能直走。
- **纠偏 / 回线**：保留 Planning 规划器的 Frenet 横向候选；兜底的 A* 改成代价感知（可通行代价 + 偏离示教线代价），与 Nav2 Smac Hybrid-A*、ETH art_planner 的思路一致。锐利台阶的立面格不再判为"未知 = 障碍"，而是带高度的"台阶边"格，由当前 policy 的能力决定能否通过。
- **跟线**：Regulated Pure Pursuit（按曲率和离障碍的距离调速），加最低速度约束（J3100 在非平地 ≥ 0.5 m/s，否则会卡在小坎上）。
- **切换 policy**：路线标注只给出"允许开始切换的区间"。真正切换由 Router 的 ALIGN 门在感知条件同时满足并保持 0.4 s 时触发：
  - 距实测台阶边 0.45–0.70 m；
  - 对实测法线的航向误差 ≤ 6°；
  - 横摆角速度 ≤ 0.1 rad/s；
  - 速度 ≤ 0.3 m/s。

  这和"检测到台阶地形进入台阶模式、通过后切回"的做法一致。
- **1150 爬升时的控制**：航向保持在实测法线 ±12° 内（它几乎不会转向）；横向只通过小角度航向偏置修正，偏置由左右落差的居中量给出；按实测前进速度压指令，因为它会超速。
- **确认通过（VERIFY_CLEAR）**：高度网格显示机身下和前方 0.3 m 没有台阶边、后轮已过最后一道边 0.6 m、俯仰 < 5°，持续 0.4 s。任何一项拿不到就判失败（fail closed）。
- **错过 WP**：1150 越过未到达的 WP 就停下，切回 J3100 原地转向补点。

## 6. 验收指标

- 仿真：每段 10 个随机种子成功率 ≥ 90%；定位偏置 0.2 m / 3° 下成功率下降不超过 10 个百分点；零摔倒；急停线（45 / 12 N·m、25.8 / 30 rad/s）越线时间计入报告。
- 真机：按 native 计划，每段连续两次通过再串联；人工接管、急停、失败分别记录，不计为成功。

## 7. 顺序

1. B + C + D 核心算法和单测。
2. E 接入 Router（ROS 无关核心 + 节点参数）。
3. F 仿真鲁棒性测试。
4. A runner 与队友对接。
5. G 现场。
