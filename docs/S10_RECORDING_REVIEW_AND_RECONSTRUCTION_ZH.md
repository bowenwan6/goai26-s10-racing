## 3. 整理经验：地形、动作和步态是三件事

保留层级：**原始录制 → 一次连续通行 → 内部片段**。

例如：

```text
一次连续上楼通行
平地接近 → 第一梯段 → 中间平台行走/转向 → 第二梯段 → 顶部平台/离开

独立的控制时间线
基础步态 → 楼梯步态 → 基础步态 → 楼梯步态 → 基础步态
```

不能每切一次步态就建立一个新通行；也不能删掉中间平台，再把两个梯段硬拼起来。步态可能提前切换，机器人也可能在楼梯上等待或在平台上保持楼梯步态。

新批次 `145331` 的实际楼梯步态约在 9.12、38.04、64.72 秒开始，中间有切回基础步态；这些是候选线索，不能直接当作接触台阶的时刻。高台 `150146` 开始时还短暂经过楼梯步态，再切为高台步态。

人工优先确认：连续通行的合并/拆分、梯段与平台的连接、上下方向、开始接触与完全离开、完成/失败/中断、是否人工干预。先确认通行结构，再细化关键边界，不要求逐一确认所有 393 个自动片段。

失败录制中的完整通过部分可以保留；成功录制中的重试、缺流和控制退出部分也必须单独处理。看不清就保留不确定，不凭姿态变化认定人工搬动。

## 4. 频率、时间和坐标的实际限制

### 频率

主 `/JOINTS_DATA` 的 5 秒源时间窗口中，185 个窗口约 200 Hz，65 个约 50 Hz，没有发现稳定的 100 Hz 档。部分整段平均接近 100 Hz，是两档混合或有效覆盖时长与录制时长不同造成的。`/JOINTS_DATA_10HZ` 是独立的约 10 Hz 话题。

网页总览只有约 10 Hz 动作、约 2 Hz 点云，这是浏览抽样，不是原始录制频率。精细回放使用原主关节时间戳，点云保留约 10 Hz 的原帧率，每帧最多抽样 6,000 点；屏幕刷新率不等于测量频率。

### 时间

索引使用 `source_stamp_ns − manifest.started_wall_ns`。纳秒原值用字符串保存，避免浏览器整数精度丢失。各话题源时间与接收时间分别保留，尚未证明跨设备时钟完全一致。

- 接收卡顿不一定是传感器缺测，先看源时间序列。
- `/GAIT` 的源戳为零，只作为接收时刻的指令线索；实际反馈看 `/MOTION_INFO`。
- STEER/HANDLE_STEER 存在异常时间间隔和数秒偏移，不能未经校准直接对齐为控制目标。
- 控制退出后，部分报告速度保持旧值，不能据此积分出持续移动的路径。
- `150921` 有状态退出、机身数据提前结束与点云长空档；`152557`、`154654` 也有控制退出。详见逐段报告。

### 坐标和回放

SDK 转换为：`仿真关节角 = 实录角 × JOINT_DIR + POS_OFFSET_RAD`，速度只乘 JOINT_DIR；四腿各 hipx/hipy/knee/wheel，共 16 通道。轮子的累计角不能像有限转角关节一样处理；当前示意轮不显示累计自转相位。

3D 页面按点云声明的 base_link 和 IMU 姿态显示，移除每段录制的初始航向。**每段内部保持同一航向原点，不同录制之间没有共同世界原点。** 机器人 XYZ 固定，点云只做姿态旋转，没有估计平移或积累地图；安装外参与数字关节映射仍需实物核对。

所以，画面可以帮助判断动作与地形阶段，但不能据此认定世界位移、逐轮接触或完整通过。人工确认应结合连续画面和现场记忆；原始数据没有相机视频。

## 5. 已做过的重建/仿真试验及结论

以下结果全部来自旧批次 `134324`，不是新 17 段的训练结果。使用本机 MuJoCo 与比赛 SDK 模型，没有启动 RL 训练。

### 关节和姿态验证

50 Hz 参考共 1,630 帧。SDK 腿关节转换往返一致，无受限关节超限；悬空运动学回放未发现超过 2 mm 的模型穿插。IMU 四元数变化与陀螺仪三轴相关系数约 0.949、0.987、0.998，支持数据内部一致性，但不能替代安装外参标定。

| 物理测试 | 腿关节 RMSE | 解释 |
|---|---:|---|
| 固定机身跟踪 12 秒 | 1.75° | 测试映射和控制跟踪 |
| 平地保持首帧 3 秒 | 1.49° | 短时站姿检查 |
| 平地运动跟踪 12 秒 | 3.65° | 未触发本轮失稳阈值，但并非越障验证 |

腿部 PD 为 kp=80、kd=2，轮子速度反馈 kd=0.6；腿/轮力矩上限分别为 50/14 Nm。参考来自实测位置、速度，**不是原厂期望动作或力矩前馈**。早期脚本曾因整数数组把轮 kd=0.6 截断为零，已修复并重跑；报告里的数字为修正后的结果。

### 假设楼梯匹配

上下楼各搜索 36 组：阶高 15/17 cm、踏面 28/30 cm、2/3/4 级、初始前轮到边缘距离 15/35/55 cm，共 72 组。

| 片段 | 假设几何 | 结果 |
|---|---|---|
| 下楼 13.4–16.4 秒 | 15 cm / 28 cm / 3 级 | 四轮通过最后一级；俯仰 RMSE 4.13°，腿关节 3.47° |
| 下楼复测 27.2–30.2 秒 | 同一尺寸与相对起始间距 | 同样通过；俯仰 RMSE 4.80°，腿关节 3.41° |
| 上楼 7.0–10.6 秒 | 17 cm / 30 cm / 2 级 | 机身抬升，但后轮未全部通过 |
| 上楼延长至 11.2 秒 | 同上 | 仿真约 4.08 秒后倾斜超过 60° |

36 个下楼候选中 25 个满足本轮终点判据，上楼候选无一满足。这说明尺寸并不唯一；不能从较小姿态误差反推“现场就是 15/28 cm、3 级”。新录制中填写的 15/55 cm 也不能与这个旧试验混为一谈。

关键经验：

1. 关节接近参考，不保证身体姿态、轮端接触和越障成功。
2. 开头几秒看起来能上楼，不等于完成；要继续播放到完全离开并稳定。
3. 同一障碍的上下楼和重复通行应约束同一个几何模型，不能每段单独挑最合适尺寸就声称重建成功。
4. 实测关节状态直接作为 PD 目标只是基线。跟踪失败可能来自目标/控制差异、接触时机或模型差异，不能直接判定原示教失败。
5. 仿真中得到的 XYZ 是假设场景里的合成路径，不能作为实机路径真值。

## 6. 人工复核区操作

1. 打开 8767 上的复核队列，先选通行或待确认问题。3D 视图显示机器人骨架和前后点云；拖动旋转、滚轮缩放，也可使用侧面/俯视按钮。
2. “循环选区”带前后各 2 秒。用播放器定位，或直接输入源秒；关键位置可“设为起点/终点”。
3. “加载精细回放”最多读取 20 秒。较长选区读取游标附近的一段，页面会注明范围；超出此范围自动使用总览采样。先加载，再慢放，不要把总览抽样当作接触级证据。
4. 选择地形、动作、方向和结果，填写障碍编号及所属连续通行。中间平台与前后梯段用相同通行编号关联；未知字段可留空或不确定。
5. “确认并保存”表示人工已审阅这条判断；“保存为无法判断”保留不确定性。保存状态显示成功后才算写入磁盘。
6. “合并前一候选区间”只扩展表单范围，检查后再保存。“拆成两段草稿”创建两条 pending 记录并重置动作、方向和结果，需要分别确认。
7. 在“已保存标注”继续修改；撤回保留历史。导出按钮下载所有录制的当前有效人工标注。

### 标注文件与多人协作

`artifacts/s10-recording-review-20260909/human_reviews.jsonl` 逐行追加修订，同一个 UUID 的最后一条为当前版本；最后版本 `retired=true` 的条目不再有效。保留时间基准、原点、起止秒、层级、地形、动作、方向、结果、关联编号、备注与保存时刻。

人工文件是独立覆盖层，**不会改写自动 passages.csv / segments.csv**。因此原列表仍可能显示 pending，最新人工进度看复核页或人工日志。后续处理要同时读取两层；重建和训练前还需要消解重叠标注和边界冲突。

多人先分配不同录制，避免重复标同一个区间。每人本地运行，检查后提交 `human_reviews.jsonl` 的新增修订，或将导出文件交给汇总者。该日志没有被忽略，但仍需显式暂存和提交。同一 UUID 的修订要人工确定最终版本，不要按文件时间或行数自动判定谁正确。不同 UUID 的重叠区间也可能是冲突，当前工具没有自动合并裁决。不要用新的导出文件覆盖整个历史日志。

### Python 环境与首次生成

当前验证平台为 Windows。本机回放环境为 Python 虚拟环境、NumPy 1.26.4、MuJoCo 3.11.0、rosbags 0.11.5；原科学图表另用了 Matplotlib 3.8.4、SciPy 1.13.1。下面把相同版本装进一个新环境，避免依赖作者的 Anaconda 用户目录；若已有兼容环境，直接复用。

```powershell
# 在项目根目录；已存在可用的 .venv-win 时跳过创建。
py -3.12 -m venv .venv-win
.venv-win/Scripts/python.exe -m pip install numpy==1.26.4 mujoco==3.11.0 rosbags==0.11.5 matplotlib==3.8.4 scipy==1.13.1

# RAW 与 SDK 路径准备好后，首次生成本机数据缓存、索引和报告。
.venv-win/Scripts/python.exe -B artifacts/s10-recording-review-20260909/review.py
.venv-win/Scripts/python.exe -B artifacts/s10-recording-review-20260909/build.py
.venv-win/Scripts/python.exe -B artifacts/s10-recording-review-20260909/plots.py
.venv-win/Scripts/python.exe -B artifacts/s10-recording-review-20260909/report.py

# 启动带保存能力的服务。
.venv-win/Scripts/python.exe -B artifacts/s10-recording-review-20260909/review_server.py
```

首次解码要读取约 15.15 GB，后续 `review.py` 会复用 decoded 缓存。换机器或数据路径时应从原录制生成缓存，不要直接复用别人的 decoded/meta 文件。`build.py` 会生成含本机 mesh 绝对路径的 XML，新机器首次不要使用 `--reuse-replay`。

只在同机已有缓存、仅更新自动候选时，才考虑 `build.py --reuse-replay`。重新生成会覆盖自动索引、静态报告和旧 validation.json，但不触碰人工日志。保留队友修改过的 observations.json；其中内容仍是候选证据，不等于人工标注。

服务只绑定 `127.0.0.1:8767`，无需机器人连接、ROS 运行环境或 Docker。当前复核不需要 GPU 训练。8766 是旧的 `http.server` 静态预览，仅浏览，不能保存或加载精细原始帧。GitHub Pages 也不能执行这里的 Python 接口。

**人工确认通行 → 局部点云配准和轨迹估计 → 拟合简单地形 → 参考运动跟踪 → 扩展训练。**

- 先选一段完整高台通行、一段包含平台连接的楼梯通行，不要求先重建整个场地或全部 17 段。
- 移动时不同点云帧不在同一观察位姿，不能直接叠加。先核对时钟/安装关系，再尝试 IMU 辅助的局部配准；重复梯面和平台可能造成配准歧义，需要检查几何重影、轨迹连续性和跨通行一致性。
- 当前点字段为 x/y/z/intensity，未记录每点 time/ring；不能不经适配就假定支持精确逐点去畸变。轮子可能打滑或离地，不可只积分轮速；也不可依赖 IMU 二次积分恢复可靠位置。
- 根据可信点云拟合阶高、踏面、级数、平台长度和朝向、高台台沿位置。在 MuJoCo/Isaac Sim 里用简单盒体表达关键接触几何，没必要复制点云每一个细节。
- 参考运动应包含腿关节角/速度、轮速、机身姿态/角速度，以及可信的局部位置/速度；轮端和接触估计需注明推断来源。给字段附上有效性与置信度，区分测量、计算、估计和仿真生成。
- 暂时没有可靠 XYZ 也可先练关节、轮速与姿态跟踪。用模仿奖励加通过障碍的任务奖励，不需要把未知的原厂动作伪造成行为克隆标签。
- 保留接近、步态过渡、平台和离开过程；随机参考状态初始化要与地形/接触一致。按完整录制或障碍划分训练和验证，避免相邻帧泄漏。若策略输入未来参考，部署时也需要可用的参考生成方式，或再蒸馏为可部署观测策略。

方法背景：[DeepMimic](https://arxiv.org/abs/1804.02717)、[四足参考运动模仿](https://arxiv.org/abs/2004.00784)、[KISS-ICP 点云里程计](https://github.com/PRBonn/kiss-icp)。这些是后续可参考的方法，不表示本项目已经实现或验证它们。
