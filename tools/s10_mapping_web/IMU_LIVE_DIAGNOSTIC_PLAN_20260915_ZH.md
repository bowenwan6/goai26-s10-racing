# AGX IMU实时诊断工具：实施计划

日期：2026-09-15。状态：计划，未开发部署；不包含自动校准或运动控制。

## 1. 目标与入口

在现有首页 `http://10.21.41.1:8080/` 新增 **IMU／停稳诊断** 按钮，拟进入 `/imu-check`。手机连接机器人热点即可操作，无需电脑、Codex或公网；页面所有脚本、样式和曲线组件本地提供。

解决的问题是：确认传感器数据是否可用、原始读数/融合反馈哪里发生变化、是否存在静止偏置或持续漂移，生成可供维修判断的证据。不能仅靠几分钟曲线证明所有标定正确，也不能直接把非零读数判成坏IMU。

## 2. 部署架构

```text
手机 → 103现有热点8080转发 → AGX（102）现有登录与新诊断页面
                                  ↓ 受限、固定协议SSH连接
                             106只读采集进程
                                  ↓ 被动订阅/只读状态
                         实际IMU、里程计、控制器反馈
```

- **AGX是工具主入口**：任务管理、实时数据转发、曲线和报告、下载归档；复用现有HTTP服务，不新开公网端口，不暴露任意shell。
- 现有代码中 `/IMU` 与 `/ODOM` 由106读取。106需要一个小型、独立的只读采集器，避免把“AGX显示的值”误称为AGX本机传感器。
- 若实际运动控制IMU或反馈源在另一台板上，先确认来源和访问权限，再决定适配；缺失显示“未接入”，不以建图IMU冒充控制器IMU。
- 不假设ROS DDS能直接跨Tailscale或全部在AGX可见；复用已验证的102→106受限SSH通道。先核实实际部署版本与主机身份。
- 诊断只依赖可用的数据源，不要求先成功加载v3或取得现有停稳资格；这不改变原现场助手切图/标点门禁。

## 3. 先确认数据语义，再采集

第一步自动盘点实际发布者、消息类型、frame_id、单位、源时间、当前启动ID与驱动版本；读取支持的初始化/校准状态。缺少运行证据则显示“未验证”，不会从 `IMUInit` 头文件或一个正常值推断已完成校准。

| 曲线/信息 | 采集内容 | 显示约束 |
| --- | --- | --- |
| 三轴角速度 | wx、wy、wz；协议单位及实际核对结果 | 默认rad/s，可显式切换deg/s；不改底层数据 |
| 三轴加速度 | ax、ay、az及模长 | 核对m/s²或g；区分是否已去重力，不能全都以零为目标 |
| 姿态变化 | 原四元数、派生roll/pitch/yaw及相对变化 | 仅有效姿态才绘制；角度跨±π不误判为跳变 |
| 运动反馈与命令 | X速度、Y速度、yaw转向速度，同图对照 | 第三项不是竖直Z速度；来自何处、单位未知必须标出 |
| 位姿变化 | 里程计位置/朝向、twist（若真实提供） | 无效/空字段不填0；融合位姿稳定不等同物理真值 |
| 时序与负载 | 观测频率、消息间隔、时间倒退/跳变、陈旧程度、队列丢弃、磁盘/CPU | 源采样时间、106接收时间、AGX到达时间分开，不将SSH抖动算成传感器抖动 |
| 温度/校准状态 | 仅设备实际提供且可只读获得的字段 | 无支持就灰色“不可用”，不伪造数值、不抢占串口 |

ROS Imu消息中零协方差表示未知，首元素−1表示该估计不可用；不能把它们当“误差为0”或有效姿态。ROS规定的单位还需核实厂商驱动实际是否遵循。[官方消息定义](https://raw.githubusercontent.com/ros2/common_interfaces/jazzy/sensor_msgs/msg/Imu.msg)

## 4. 采集与实时可视化

- 独立采集器按实际发布频率接收可获得的全部消息；200Hz仅为历史配置参考。现有10Hz角速度预览不能作为该诊断的原始输入。
- ROS订阅QoS依据发布者核实，采用兼容的被动订阅；不为采集改变发布者可靠性或驱动频率。记录收到数量和本地队列溢出，不能没有硬件序号却声称精确知道全部传感器丢包。[官方QoS规则](https://raw.githubusercontent.com/ros2/ros2_documentation/jazzy/source/Concepts/Intermediate/About-Quality-of-Service-Settings.rst)
- 第一版只采IMU、位姿、必要命令与反馈，不额外采大点云；避免增加不必要的带宽和处理负载。
- 浏览器约5～10次/秒更新，显示最近30秒，可展开120秒。每个显示桶保留min/max包络与均值，不用稀疏抽点隐藏尖峰。统计基于完整已接收采样，不基于显示抽样。
- 展示原值曲线、滑动均值和波动范围，固定/自动量程可切换；每张图标明单位和时间窗。跨主机时间不能核实时，只显示同一采集主机的接收时间对照，禁止强行对齐。
- 断流画空白并标记最后更新时间，不把旧值画成持续平直；跨启动/重新初始化不拼成一条连续趋势。
- AGX用单一后台连接取增量批次；首版可用5Hz带游标轮询，避免现有HTTP线程被多个长连接占满。多手机共享同一个采集任务，不能各启动一份传感器订阅。

## 5. 手机操作流程

1. 点 **查看实时数据**：只观察，不要求停稳，不改变任何控制状态。
2. 点 **开始180秒静止检查**：提示“让机器人安全站稳、退出外部policy/导航、手柄可接管”。人工确认只作为取证标签，不证明机器人真的静止。
3. 页面展示倒计时、进度、已收样本和数据质量；移动/振荡会标记该段不适合作为零偏基线，不自动重置任务无限等待。
4. 可点 **标记刚刚停稳／刚刚移动** 添加事件，以便对照瞬态；手柄操作仍由人完成，网页不发送运动命令。
5. 到时自动结束，生成结果。默认180秒，计划支持60/180/300秒；连续观察不自动永久录盘。
6. 点 **下载报告和数据**；以后可在历史任务中恢复查看。

主要按钮：查看实时数据、开始静止检查、标记事件、结束并保存、历史结果、下载。

**不提供“自动校准”“强制归零”“放宽门槛”“启动policy”按钮。** “结束采集”不是停车或急停。

## 6. 分析与结论展示

每10秒窗口计算均值、标准差、峰值、分位数、均值变化；分轴显示，不把正负快速振荡的均值0当静止。温度可用时添加相关曲线，但不仅凭相关性推断温漂根因。

报告分开显示：

- 数据可用性：采样是否完整到足以分析、时序是否可比、字段是否有效。
- 静止基线有效性：人工标签、命令源状态、实际运动/位姿证据是否一致；证据不足为“未确定”。
- 信号表现：稳定偏置候选、明显时变趋势、波动/振荡、陈旧反馈等，以及数值与片段链接。
- 校准状态：已确认/未验证/设备不支持读取，而不是一句“IMU正常”。
- 建议处理层：传感器初始化/补偿、融合或控制器状态估计、App判定，或证据不足。

可在报告里给出“静止条件下的角速度偏置估计”，必须标明来源、姿态/温度/时段、波动和限制；不得自动写回。单一站姿不能可靠完成完整加速度标定，不能盲减重力。

在型号规格和实际静止统计未确认前，不编造统一PASS阈值。诊断结论不自动解锁切图/标点/导航，也不重新开启v3或B段几何根因审计。

## 7. 保存、恢复及资源保护

- 106先保存源消息与采集时间，AGX同步诊断摘要、分片数据与最终导出包。拟定106独立目录 `/var/opt/robot/data/s10_imu_diagnostics/<session_id>/`，AGX独立目录 `/home/golai/.local/share/s10-imu-check/<session_id>/`；部署前核对挂载、权限、空间。
- 导出：`manifest.json`（身份、版本、话题、单位、QoS、时间基准）、源消息归档、CSV、事件、时序/完整性统计、JSON报告和离线HTML曲线。按消息类别区分原始传感器、驱动输出和融合值，不把全部统称硬件原始数据。
- 浏览器锁屏/关闭或AGX↔106断网时，106正在进行的限时任务继续到上限并落盘；恢复后按session ID和游标补取。断电不能保证尾部已落盘数据完整，重启后标记“中断/部分保存”，不冒充成功。
- 任务ID、重复提交键、单采集实例和原子元数据更新；断线重试不能启动第二个任务。未标定的时钟变化不破坏单调时钟时限。
- 本地写入队列有界、定期持久化；初始录制上限300秒/单任务256MiB、保留磁盘至少2GiB，按实测调整资源预算而非传感器频率。达到上限结束并报告原因，不删除旧结果腾空间。
- 复用受限SSH固定操作白名单和现有登录/CSRF；没有任意话题shell、路径穿越或匿名任务启动。导出不包含密钥/密码。
- 不直接复用原10～30秒field recorder的时限假装支持180秒；单独实现诊断作业生命周期，避免改变现有验图录制行为。

## 8. 实施顺序与验收

### A：只读接入确认

确认102/106现状、IMU身份/来源、字段、发布频率和消息类型。无法接入原始数据时先报告实际可得范围；不得静默降为网页10Hz预览。

### B：本地开发与离线测试

拟新增 `imu_diag_core.py`、106 `imu_diag_collector.py`、AGX任务/转发模块、`imu_diag.html/js` 与测试；在首页添加入口。先用明确标记的合成/回放数据测试，生产模式不得自动回退为demo。

测试覆盖：稳定噪声、固定偏置、随时间漂移、正负振荡、NaN、无效姿态/协方差、陈旧消息、重复/跳变时间、两路IMU混淆、断网恢复、重复点击、磁盘不足和进程重启。

### C：实机只读试运行

备份部署文件，仅启用诊断服务；不重启传感器、SLAM或控制器。网页服务如需重启，在没有进行中的用户任务时安排维护窗口。先检查短采集和CPU/内存/队列，再运行一次180秒静止检查。

### D：手机离线验收

关闭手机蜂窝数据/公网，仅连机器人热点，冷启动访问现有首页进入诊断；确认无需CDN、曲线真实更新、等待进度可见、锁屏恢复不丢任务。测试断网、数据源断流的区别及导出完整性。

### 放行条件

1. 页面与源采样抽查一致，单位/来源明确；原频率接收与显示刷新分开。
2. 未知和断流明确显示，不补0、不保持假实时曲线。
3. 默认180秒任务能完成、保存、恢复和导出，重复点击不重复采集。
4. 同时有实时预览和数据质量统计，后台丢弃/部分保存不隐瞒。
5. 资源开销实测可接受，未导致原系统新增明显延迟/丢帧；若影响原任务则停诊断并保留证据。
6. 没有发布运动/导航指令、修改厂商参数、切图或执行校准；原现场助手保护和已有功能回归通过。

验收通过只说明诊断工具可用，不说明IMU已经校准或机器人可自主运行。

## 9. 本轮交付边界

当前只提交该计划。开发后交付AGX页面/脚本、必要106只读采集器、手机操作说明、样本报告、测试与回滚记录。实际校准或停稳门禁修改需要依据诊断结果另行实施，不混入本工具首版。

本计划使用Calibration Tools方法，明确区分传感器校准、估计器输出与显示层，并保留原始测量证据。
