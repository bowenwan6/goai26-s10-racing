# 采集助手（新 SLAM）使用说明

2026-09-19。手机网页 `/teach`，给新 SLAM（x_nav）做三件事：

1. **建图采集**：录点云 + IMU + 位姿，走带回环的大圈。
2. **标点**：WP01–WP30、policy 切换点（▲SWIN 进台阶 / ▼SWOUT 出台阶）。
3. **示教路径**：连续录一遍最短可行的手动路线。

**本页只记录数据，不控制机器人。** 行走和急停一律用遥控器。

**状态：**
- 已在 AGX 上部署，AGX 原生测试通过：真实 ROS 模式和网页端到端各一套。
- **新狗（050 号）09-19：** 后台已接通 x_nav 位姿 `/base_link/odom`、点云、IMU（10 / 10 / 199 Hz）。手机经机器人 Wi-Fi 访问、实际标点和录包还没验证。
- 背景和整体计划见仓库 `docs/NEW_SLAM_XNAV_INTEGRATION_ZH.md`。

## 1. 每次上场前：启动（约 1 分钟）

| 顺序 | 在哪 | 命令 | 作用 |
|---|---|---|---|
| 1 | Mac（仓库目录） | `bash ros1_gateway/scripts/robot_session.sh up` | 部署并启动 106 点云 tap，启动 AGX 上的 ROS 1 master 和网关。会提示操作员输入 106 密码 |
| 2 | AGX（ysc） | `cd /opt/data/compose && sudo docker compose up -d` | 启动 x_nav（建图 / 定位） |
| 3 | AGX（golai） | `bash ~/s10_mapping_web/teach-worker.sh start --pose-topic /base_link/odom` | 启动采集助手后台 |

- 第 1 步也可以手动做：AGX 上 `bash ~/ros1_gateway/scripts/start_gateway.sh`，106 上 `bash ~/ros1_gateway_tap/run_tap_106.sh start`。
- **位姿话题：** 新狗实测 x_nav 输出 `/base_link/odom`（10 Hz）。换版本后可以在 AGX 上再查一次：

  ```bash
  source ~/ros1_gateway/ros1/ros1_env.sh && rostopic list | grep -i -E "odom|pose"
  ```

- **x_nav 没启动或出问题时：** 建图采集照样能录点云和 IMU，以后离线建图。
- **手机打开：** 连机器人 Wi-Fi，浏览器输入 `http://10.21.33.102:8080/teach`，账号沿用原网页登录。
  - 旧狗时的 `10.21.41.1:8080` 是 103 上的转发，新狗上没有。
  - 如果 `10.21.33.102` 也打不开，现场用电脑 SSH 确认路由，或让负责人改用 AGX 的 Wi-Fi 地址。

## 2. 页面怎么看

- **顶部状态条：** 点云（约 10 Hz）、IMU（约 200 Hz）、定位、磁盘剩余、录制状态。绿 = 正常，黄 = 偏低，红 = 没有数据。
- **提示条：** 有问题时写明原因，例如“没有新 SLAM 位姿”“ROS 1 master 未运行”。
- **会话：** 每次上场先“新建会话”（名字用字母 / 数字）。所有录制和标点都存在这个会话里。已有会话时表单会折叠。
- **俯视图：**
  - 蓝线 = 轨迹（示教时是橙色），红色箭头 = 机器人。
  - 绿圆 = WP（数字是编号），紫三角 = 切换点（▲进台阶，▼出台阶），黄圆 = 建图起点。
  - “全览”看整条路，“跟随机器人”看周围 20 m。
- **四个标签：** ① 建图　② 标点　③ 示教　④ 数据。

## 3. ① 建图（点云 + IMU，带回环）

**为什么要回环：** 赛道是一条长线，只走单程，远端误差会越积越大。往返走、最后回到起点，SLAM 才能把整条路修正一致。

1. 在 WP01 地上贴好“脚印框”：前两脚位置加朝向箭头。机器人放进去，朝赛道方向停稳。
2. （x_nav 可用时）按厂商说明开始建图。
3. 点 **开始采集**。页面会检查：点云、IMU 有数据，磁盘剩余 ≥ 20 GB。
4. **原地静止 5 秒**，再用遥控器慢慢走到 WP30：平地 0.3–0.5 m/s，转弯要慢，避开人群。
5. 在 WP30 附近掉头，**沿原路走回**，停回脚印框（位置、朝向都对上），**静止 5 秒**。
6. 点 **结束采集**。然后在 x_nav 保存地图，把地图名记下来（下次新建会话时填进去）。

**说明：**
- 页面上的“距起点”是用新 SLAM 自己的位姿算的，只作参考。回到起点**以地上的脚印框为准**。回环修正后这个数字应接近 0。
- 数据约 1.5 GB/分钟，每 2 GB 自动分一个文件；磁盘剩余低于 3 GB 会自动停止。

## 4. ② 标点（WP 与切换点）

**前提：** x_nav 已进入**定位模式**，加载的是刚保存的最终地图，并在 WP01 脚印框重定位成功。

> 建图时不能标点：回环会把之前的位姿整体修正，边建边标的坐标之后会对不上。

1. 点 **开始录制标点数据**（推荐，结束后点“结束录制”）。
2. **标 WP：**
   - 在方格里选编号（**正式顺序：WP01 = 门口 Start，WP30 = 远端**；和照片顺序相反）。
   - 机器人机身中心对准红点、朝向下一个 WP、停稳。
   - 点 **标 WPxx（停稳 3 秒）**，采样期间别动。
   - 结果：
     - 绿色“✓ 已保存”，自动跳到下一个没标的 WP。
     - 黄色：合格但离散偏大，建议重标。
     - 红色“✗ 不合格”：原因会写出来（通常是没停稳），停稳后再点一次。
   - 合格标准：3 秒内位置离散 ≤ 2 cm、朝向 ≤ 1°。
3. **标切换点（成对）：**
   - **▲ SWIN（交给台阶 policy）：** 停在第一级台阶或坎前 0.3–0.5 m 的平地上，**机身正对台阶边**，点按钮。
   - **▼ SWOUT（交还步行 policy）：** 停在最后一级之后、**离边缘 ≥ 0.5 m** 的稳定平地上，点按钮。
   - 页面会显示“已标 N 对”；如果有 ▲ 还没配 ▼，会提醒。
   - 需要成对标的地方：B 楼梯及中间平台、WP03→WP04 小台阶、石笼坎、人工台 / 黄色凸台、乱石溪床。WP11 岩脊、WP14 的 0.19 m 坎、B 楼梯第一级要特别仔细。
4. **标错了：** 点 **作废上一个标记**，再重标。原记录不删除，只标为作废。
5. **备注：** 站不上红点、旗子有两面等情况，写在备注里。例如“WP16 两面旗取左边”“WP11 未站上红点，偏右约 30 cm”。
6. **先测低置信度的点：** WP16、24、25、27、28、30、WP06、WP07。
7. **复测：** 全部标完后，回到 WP01、WP10、WP20 各再标一次，看前后差（离线计算）。

## 5. ③ 示教（最短手动路径）

**前提：** x_nav 在定位模式，机器人在 WP01 脚印框。

1. 点 **开始示教**，用遥控器**连续**走完 WP01 → WP30，中途不用停。
2. 走线规则（来自两个 policy 的实测能力）：

   | 场景 | 规则 |
   |---|---|
   | 平地 | 尽量走直线；开阔处可以切弯，离边缘、障碍 ≥ 0.5 m |
   | 进台阶前 | 留 ≥ 1 m 直线，**垂直**正对台阶边，不贴台阶侧边走 |
   | 台阶上 | 不转弯，走台阶中间 |
   | 坡 | 避开 > 6° 的侧坡 |
   | 台阶高度 | 不走 > 18 cm 的台阶 |
   | 落差 | 离落差 ≥ 0.4 m |
   | 低矮树冠（WP29 附近） | 选机身能通过的位置 |

3. （可选）经过某个 WP 时，在下拉框选中它，点 **记录经过**（不用停车）。
4. 到 WP30 点 **结束示教**。页面显示路径长度、用时、平均速度。
5. **最好完整走两遍**，离线选更短、更平顺的一遍。

## 6. ④ 数据

- **位置：** AGX 的 `~/teach/sessions/<会话名>/`

  | 文件 | 内容 |
  |---|---|
  | `session.json` | 会话信息（地图名、位姿话题） |
  | `marks.jsonl` | 所有标点和结果；作废记录也在 |
  | `recordings.jsonl` | 每次录制的开始 / 结束、文件、回环距离、路径长度 |
  | `mapping_*.bag` / `survey_*.bag` / `path_*.bag` | ROS 1 数据包，标点也以 `/teach/mark` 话题写在包里 |
  | `*.trail.csv` | 录制期间的位姿轨迹（手机也能下载） |

- **小文件**在页面上直接点击下载。**`.bag` 很大，用电脑拷贝：**

  ```bash
  scp -r golai@10.21.33.102:~/teach/sessions/<会话名> .
  ```

- “设为当前会话”可以回到旧会话继续标点，已有的标点会恢复显示。
- **不要删除或覆盖任何文件。** 当天结束把会话名、x_nav 地图名、特殊情况告诉负责人。

## 7. 常见问题

| 页面提示 | 原因与处理 |
|---|---|
| 采集助手后台未启动 | 在 AGX 执行 `bash ~/s10_mapping_web/teach-worker.sh start …` |
| ROS 1 master 未运行 | 先执行 `start_gateway.sh` |
| 没有新 SLAM 位姿 | x_nav 没启动，或位姿话题名不对（`teach-worker.sh stop` 后用正确的 `--pose-topic` 重启） |
| 位姿话题类型不支持 | 目前支持 `nav_msgs/Odometry`、`PoseStamped`、`PoseWithCovarianceStamped` |
| 点云 / IMU 无数据 | 网关没启动，或 106 的 tap 没启动（`health_check.sh` 查看） |
| 标点总是不合格 | 机器人没停稳，或定位在跳。看原因里的离散数值；静止还超过 2 cm 说明定位有问题，先解决定位 |
| 录制自动停止 | 磁盘剩余不足 3 GB，或录制进程退出（看会话目录里的 `*.record.log`） |
| ROS master 重启过 | 后台会自动重启重连，等几秒即可 |

## 8. 停止

```bash
bash ~/s10_mapping_web/teach-worker.sh stop
```

后台停止时，如果还在录制，会先把正在录的包正常收尾，再退出。

收工时在 Mac 上复原共用的机器人：停止并删除 106 上的 tap；加 `--agx` 同时停掉 AGX 网关。

```bash
bash ros1_gateway/scripts/robot_session.sh down --agx
```

## 9. 培训 / 演示模式

没有机器人时，可以在 AGX 上启动演示模式练习：模拟一只机器人在走，每个拐角停 8 秒，可以练习标点。页面顶部会显示红色“演示模式”，不会录真实数据包。

```bash
bash ~/s10_mapping_web/teach-worker.sh start --fake
```
